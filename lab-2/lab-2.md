# Лабораторна робота № 2

## Пікселі, RGB/RGBA та ImageData

## Мета

Навчитися безпосередньо працювати з пікселями Canvas: визначати положення
пікселя в одновимірному масиві, читати й змінювати компоненти RGBA, формувати
растрове зображення подвійним циклом за координатами та реалізовувати прості
піксельні ефекти за допомогою `ImageData`.

## Теоретичні відомості

### Піксель і колірна модель RGB

Растрове зображення складається з прямокутної сітки пікселів. Кожний піксель
має координати `(x, y)`, де початок координат Canvas розташований у лівому
верхньому куті. Координата `x` збільшується вправо, а `y` — вниз. Для Canvas
розміром `640 × 480` допустимими є значення `x` від `0` до `639` і `y` від `0`
до `479`.

У колірній моделі **RGB** колір утворюється додаванням трьох компонентів:

- R — інтенсивність червоного;
- G — інтенсивність зеленого;
- B — інтенсивність синього.

У `ImageData` кожний канал подано цілим числом від `0` до `255`. Значення `0`
означає відсутність відповідної складової, а `255` — її максимальну
інтенсивність. Наприклад, `(255, 0, 0)` задає червоний, `(0, 255, 0)` —
зелений, `(0, 0, 255)` — синій, `(255, 255, 255)` — білий, а `(0, 0, 0)` —
чорний колір.

### Альфа-канал і модель RGBA

Модель **RGBA** доповнює RGB четвертою компонентою A — альфа-каналом. Він
визначає непрозорість пікселя:

- `A = 0` — піксель повністю прозорий;
- `A = 255` — піксель повністю непрозорий;
- проміжні значення — піксель частково прозорий.

Альфа-канал не є окремим кольором. Він визначає, якою мірою колір пікселя
поєднується з тим, що розташовано позаду Canvas. У стартовому шаблоні під
Canvas задано клітинчасте CSS-тло, тому прозорі й напівпрозорі ділянки можна
побачити без додаткового зображення.

### Об’єкт ImageData

Об’єкт `ImageData` зберігає ширину, висоту та послідовність каналів усіх
пікселів прямокутної ділянки:

```js
const imageData = context.createImageData(canvas.width, canvas.height);

console.log(imageData.width);
console.log(imageData.height);
console.log(imageData.data);
```

Властивість `data` має тип `Uint8ClampedArray`. Це одновимірний масив, у якому
кожному пікселю відповідають чотири послідовні елементи в порядку R, G, B, A:

```text
[R, G, B, A, R, G, B, A, R, G, B, A, ...]
```

Довжина масиву дорівнює `width * height * 4`. Тип `Uint8ClampedArray`
автоматично обмежує записані числа діапазоном `0–255`. Однак формули все одно
потрібно складати свідомо: автоматичне обмеження не виправляє логічну помилку
в обчисленні кольору.

### Адресація пікселів

Пікселі записано рядок за рядком: спочатку весь рядок `y = 0`, потім рядок
`y = 1` і так далі. Порядковий номер пікселя з координатами `(x, y)` дорівнює
`y * width + x`. Оскільки один піксель займає чотири елементи масиву, індекс
його червоного каналу обчислюють так:

```js
const pixelIndex = 4 * (y * width + x);
```

Інші канали цього пікселя розташовано за сусідніми індексами:

```js
pixels[pixelIndex] = red;
pixels[pixelIndex + 1] = green;
pixels[pixelIndex + 2] = blue;
pixels[pixelIndex + 3] = alpha;
```

Наприклад, для пікселя `(3, 2)` у зображенні завширшки `10` пікселів індекс
червоного каналу дорівнює `4 * (2 * 10 + 3) = 92`. Канали цього пікселя мають
індекси `92`, `93`, `94` і `95`.

Типова структура обходу всього зображення має вигляд:

```js
for (let y = 0; y < height; y += 1) {
  for (let x = 0; x < width; x += 1) {
    const pixelIndex = 4 * (y * width + x);
    // Читання або запис R, G, B, A.
  }
}
```

Умова циклу повинна містити `< width` і `< height`, а не `<=`. Координати
`x = width` і `y = height` уже розташовані за межами зображення.

### Створення, читання й виведення ImageData

Метод `createImageData(width, height)` створює новий прозоро-чорний буфер
потрібного розміру. Після заповнення його потрібно вивести на Canvas методом
`putImageData`:

```js
const imageData = context.createImageData(width, height);

// Заповнення imageData.data.

context.putImageData(imageData, 0, 0);
```

Метод `getImageData(x, y, width, height)` копіює поточні пікселі вказаної
ділянки Canvas до нового об’єкта `ImageData`. Це дає змогу прочитати наявні
кольори, змінити їх у масиві та повернути результат:

```js
const imageData = context.getImageData(0, 0, canvas.width, canvas.height);
const pixels = imageData.data;

// Зміна pixels.

context.putImageData(imageData, 0, 0);
```

`putImageData` записує передані пікселі безпосередньо. На нього не впливають
поточні `fillStyle`, `globalAlpha`, матриця перетворення чи контур Canvas.

### Нормування координат

Щоб крайні значення градієнта наближалися до `0` і `255` незалежно від
розміру Canvas, координату можна нормувати:

```js
const red = Math.round((x / (width - 1)) * 255);
const green = Math.round((y / (height - 1)) * 255);
```

Для `x = 0` значення `red` дорівнює `0`, а для `x = width - 1` — `255`.
Ділення саме на `width - 1` дає змогу досягти максимального значення на
останньому допустимому пікселі.

### Піксельні ефекти

Піксельний ефект — це правило, за яким вихідні канали обчислюються на основі
поточних каналів або координат пікселя. Наприклад, для інверсії кожний
колірний канал замінюють його доповненням до `255`:

```js
pixels[pixelIndex] = 255 - pixels[pixelIndex];
pixels[pixelIndex + 1] = 255 - pixels[pixelIndex + 1];
pixels[pixelIndex + 2] = 255 - pixels[pixelIndex + 2];
```

Під час перетворення на градації сірого нове значення можна обчислити як
зважену яскравість:

```js
const brightness = Math.round(0.299 * red + 0.587 * green + 0.114 * blue);
```

Після цього `brightness` записують до R, G і B, а альфа-канал зазвичай
залишають без змін. Для порогового перетворення яскравість порівнюють із
порогом і записують `0` або `255`.

Повторне застосування деяких ефектів змінює результат ще раз. Наприклад,
подвійна інверсія повертає вихідні кольори, а повторне зменшення яскравості
поступово робить зображення чорним. Тому сторінка повинна мати окрему кнопку
для відновлення початкового зображення. У стартовому шаблоні ця кнопка та її
обробник уже наявні: обробник повторно викликає функцію формування базового
зображення.

### Зовнішні зображення та обмеження доступу

Якщо для додаткового ефекту використовується зовнішній растровий файл, його
потрібно зберігати локально в проєкті й дочекатися завершення завантаження
перед викликом `drawImage` та `getImageData`. Зображення з іншого домену без
належного дозволу CORS може зробити Canvas недоступним для читання пікселів.
У такому разі браузер з міркувань безпеки викине виняток під час виклику
`getImageData`.

## Хід роботи

### 1. Підготовка проєкту

1. Скопіювати стартовий Vite-проєкт із файлами `index.html`, `src/main.js` і
   `src/style.css` до окремої теки.
2. Запустити проєкт у режимі розробки та відкрити сторінку в Chrome або Edge.
3. Відкрити інструменти розробника й переконатися, що в консолі немає помилок.
4. Указати в заголовку сторінки прізвище та ім’я, групу й номер варіанта.
5. Переконатися, що на сторінці вже наявні кнопки застосування ефекту та
   відновлення початкового зображення. Кнопку скидання вилучати не можна.

### 2. Створення базового RGBA-зображення

1. Використати Canvas із внутрішніми розмірами не менше `320 × 240` пікселів.
   У шаблоні задано розмір `640 × 480`.
2. У функції `drawInitialImage` створити об’єкт `ImageData` розміром Canvas.
3. Отримати посилання на масив `imageData.data`.
4. Організувати зовнішній цикл за `y` і вкладений цикл за `x`.
5. Для кожного пікселя обчислити індекс за формулою
   `4 * (y * width + x)`.
6. Обчислити канали базового зображення:
   - червоний канал повинен змінюватися вздовж горизонтальної осі;
   - зелений канал повинен змінюватися вздовж вертикальної осі;
   - синій канал потрібно визначити за правилом свого варіанта;
   - хоча б в одній помітній ділянці альфа-канал має відрізнятися від `255`.
7. Записати R, G, B і A безпосередньо до чотирьох елементів масиву.
8. Вивести готовий об’єкт методом `context.putImageData(imageData, 0, 0)`.
9. Описати на сторінці правило обчислення B та умову зміни A.

Заміна цієї частини готовим CSS-градієнтом, `createLinearGradient`,
`fillRect`, SVG або растровим файлом не допускається. Базове зображення має
бути сформоване через `ImageData.data`.

### 3. Реалізація піксельного ефекту

1. У функції `applyEffect` отримати поточні пікселі Canvas за допомогою
   `getImageData`.
2. Обійти всі пікселі подвійним циклом.
3. Для кожного пікселя прочитати потрібні значення R, G, B та A.
4. Обчислити нові значення відповідно до свого варіанта.
5. Записати змінені канали до того самого масиву.
6. Після завершення циклів один раз викликати `putImageData`.
7. Переконатися, що натискання кнопки «Застосувати ефект» викликає функцію
   ефекту та змінює зображення.
8. Доповнити текстовий опис реалізованого ефекту на сторінці.

Не потрібно викликати `getImageData` або `putImageData` для кожного пікселя
окремо. Дані всього зображення отримують один раз, змінюють у масиві, а потім
одним викликом повертають на Canvas.

### 4. Відновлення початкового стану

1. Не змінювати ідентифікатор `reset-image-button`, передбачений стартовим
   шаблоном.
2. Зберегти обробник кнопки, який викликає `resetImage`.
3. У функції `resetImage` повторно викликати `drawInitialImage`, щоб результат
   не залежав від кількості попередніх застосувань ефекту.
4. Перевірити послідовність: застосувати ефект кілька разів, відновити
   зображення, ще раз застосувати ефект.
5. Переконатися, що після відновлення зображення точно відповідає початковому
   результату.

### 5. Перевірка результату та оформлення звіту

1. Перевірити кольори в чотирьох кутах і приблизно в центрі Canvas.
2. Переконатися, що напівпрозора або прозора ділянка помітна на клітинчастому
   тлі.
3. Перевірити роботу обох кнопок і повторне застосування ефекту.
4. Перевірити відсутність помилок у консолі браузера.
5. Зробити окремі скриншоти початкового та зміненого зображень.
6. Підготувати звіт із формулами каналів, ключовим фрагментом циклу та
   відповідями на контрольні запитання.

## Варіанти

Номер варіанта відповідає порядковому номеру студента у списку групи. Якщо
порядковий номер перевищує 20, варіант визначають за формулою
`((N - 1) mod 20) + 1`, де `N` — номер студента у списку.

У формулах таблиці `x` і `y` — координати пікселя, `width` і `height` —
розміри Canvas, а `R` і `G` — уже обчислені значення червоного й зеленого
каналів. Результат для B потрібно округлити за потреби. Вирази з остачею від
ділення записано оператором `%`.

| № | Правило для синього каналу B | Ділянка зі зміненим A | Піксельний ефект |
| ---: | --- | --- | --- |
| 1 | `(x + y) % 256` | центральне коло, `A = 128` | інверсія RGB |
| 2 | `Math.abs(R - G)` | ліва вертикальна смуга, `A = 110` | градації сірого |
| 3 | `255 - Math.round((R + G) / 2)` | правий верхній прямокутник, `A = 140` | порогове перетворення, поріг `128` |
| 4 | `Math.round(127.5 * (1 + Math.sin(x / 18)))` | нижня горизонтальна смуга, `A = 100` | шаховий візерунок блоками `24 × 24` |
| 5 | `Math.round(127.5 * (1 + Math.cos(y / 20)))` | кільце навколо центра, `A = 130` | пікселізація блоками `8 × 8` |
| 6 | `(2 * x + y) % 256` | головна діагональна смуга, `A = 120` | градації сірого |
| 7 | `(x + 2 * y) % 256` | побічна діагональна смуга, `A = 120` | порогове перетворення, поріг `96` |
| 8 | `(R + G) % 256` | центральний прямокутник, `A = 96` | шаховий візерунок блоками `32 × 32` |
| 9 | `Math.min(255, 2 * Math.abs(R - G))` | два вертикальні прямокутники, `A = 150` | пікселізація блоками `10 × 10` |
| 10 | `Math.round(Math.sqrt(R * G))` | верхня горизонтальна смуга, `A = 115` | інверсія RGB |
| 11 | `Math.round((R + 2 * G) / 3)` | коло в лівій половині, `A = 125` | градації сірого |
| 12 | `Math.round((2 * R + G) / 3)` | коло в правій половині, `A = 125` | порогове перетворення, поріг `160` |
| 13 | `(Math.floor(x / 16) * 32) % 256` | кожна четверта вертикальна смуга, `A = 135` | кольорові вертикальні смуги завширшки `20` пікселів |
| 14 | `(Math.floor(y / 16) * 32) % 256` | кожна четверта горизонтальна смуга, `A = 135` | пікселізація блоками `12 × 12` |
| 15 | `(Math.floor(x / 24) + Math.floor(y / 24)) % 2 * 255` | центральний ромб, `A = 105` | кольорові смуги за координатою `x` |
| 16 | `Math.round(255 * x * y / ((width - 1) * (height - 1)))` | еліпс у центрі, `A = 145` | пікселізація блоками `16 × 16` |
| 17 | `Math.round(255 * (1 - x / (width - 1)) * (1 - y / (height - 1)))` | чотири кутові квадрати, `A = 90` | порогове перетворення, поріг `170` |
| 18 | `Math.round(127.5 * (1 + Math.sin((x + y) / 22)))` | хвиляста смуга навколо середини, `A = 130` | градації сірого з підсиленням контрасту |
| 19 | `Math.round(127.5 * (1 + Math.sin(Math.hypot(x - width / 2, y - height / 2) / 12)))` | центральний круг, `A = 80` | радіальні чорно-білі кільця |
| 20 | `(Math.floor(x / 20) * 37 + Math.floor(y / 20) * 53) % 256` | шахові блоки `40 × 40`, `A = 120` | власна пікселізація блоками `12 × 12` |

Умова прозорої ділянки повинна перевірятися в коді за координатами. Її межі
студент добирає так, щоб ділянка була добре помітною, але не приховувала все
зображення. Альфа-канал інших пікселів має дорівнювати `255`.

Для дзеркального відображення та пікселізації може знадобитися окрема копія
вихідного масиву, щоб запис уже зміненого пікселя не впливав на читання
наступних. Її можна створити так:

```js
const sourcePixels = new Uint8ClampedArray(imageData.data);
```

## Обов’язковий результат

- базове зображення розміром не менше `320 × 240`, сформоване через
  `ImageData.data`;
- горизонтальна зміна R, вертикальна зміна G і власне правило для B;
- помітна ділянка, у якій альфа-канал відрізняється від `255`;
- один завершений піксельний ефект відповідно до варіанта;
- працездатні кнопки застосування ефекту та відновлення початкового стану;
- правильна адресація пікселів і відсутність помилок у консолі.
