# Лабораторна робота № 3

## Програмна растеризація трикутника

## Мета

Навчитися задавати трикутник в екранних координатах, обчислювати його
обмежувальний прямокутник, визначати належність центра пікселя трикутнику за
допомогою барицентричних координат або edge-функцій та будувати одноколірний
трикутник безпосереднім записом до `ImageData.data`.

## Теоретичні відомості

### Растеризація геометричного примітива

Трикутник задають трьома вершинами `A`, `B` і `C` у неперервній системі
екранних координат. Canvas, на якому потрібно показати результат, складається
зі скінченної прямокутної сітки пікселів. **Растеризація** — це визначення
пікселів, які покриває геометричний примітив, і створення відповідних
фрагментів для подальшого запису кольору.

У цій роботі кожний покритий фрагмент одразу перетворюється на одноколірний
піксель. У складнішому графічному конвеєрі фрагмент ще може проходити
тестування глибини, обчислення освітлення, змішування з наявним кольором та
інші операції. Тому фрагмент і остаточний піксель не завжди є тим самим.

Canvas має початок координат у лівому верхньому куті. Координата `x`
збільшується вправо, а `y` — вниз. Для Canvas розміром `640 × 480` допустимі
цілі координати пікселів:

```text
0 <= x < 640
0 <= y < 480
```

Готові команди `fill()`, `fillRect()` або SVG-фігури вже містять реалізацію
растеризації всередині браузера. Їх використання для заповнення трикутника не
дає змоги дослідити coverage test, тому внутрішню область потрібно створити
саме записом пікселів до `ImageData.data`.

### Центр пікселя та coverage test

Піксель із цілими координатами `(x, y)` займає квадрат від `(x, y)` до
`(x + 1, y + 1)`. У цій роботі представницькою точкою пікселя є його центр:

```js
const point = {
  x: x + 0.5,
  y: y + 0.5,
};
```

Піксель вважають покритим, якщо ця точка розташована всередині трикутника або
на його межі. Перевірка в усіх центрах створює однозначне правило
дискретизації: результат не залежить від випадково вибраного кута пікселя.
Водночас це лише одна вибірка на піксель, тому похилі ребра без
згладжування матимуть характерний ступінчастий вигляд.

### Орієнтована edge-функція

Для точок `A`, `B` і `P` зручно використати двовимірний векторний добуток:

```text
edge(A, B, P) =
  (B.x - A.x) * (P.y - A.y) -
  (B.y - A.y) * (P.x - A.x)
```

Модуль результату дорівнює площі паралелограма, утвореного векторами `AB` і
`AP`. Знак показує, з якого боку орієнтованого ребра `A -> B` лежить точка
`P`. Для трьох вершин трикутника значення
`edge(A, B, C)` дорівнює подвоєній орієнтованій площі трикутника.

```js
function edgeFunction(start, end, point) {
  return (
    (end.x - start.x) * (point.y - start.y) -
    (end.y - start.y) * (point.x - start.x)
  );
}
```

Якщо поміняти місцями дві вершини, геометрична область трикутника не
зміниться, але знак орієнтованої площі стане протилежним. Тому алгоритм не
повинен припускати лише один порядок обходу вершин.

### Барицентричні координати

Будь-яку точку `P` у площині невиродженого трикутника можна подати як
комбінацію його вершин:

```text
P = lambdaA * A + lambdaB * B + lambdaC * C
lambdaA + lambdaB + lambdaC = 1
```

Коефіцієнти `lambdaA`, `lambdaB` і `lambdaC` називають барицентричними
координатами. Через edge-функції їх можна обчислити так:

```text
area = edge(A, B, C)

lambdaA = edge(B, C, P) / area
lambdaB = edge(C, A, P) / area
lambdaC = edge(A, B, P) / area
```

Для точки всередині трикутника всі три координати невід’ємні. На ребрі одна
з них дорівнює нулю, а у вершині дві координати дорівнюють нулю. Ділення на ту
саму орієнтовану площу робить формулу придатною для обох порядків обходу:
чисельники й знаменник одночасно змінюють знак.

Через похибки обчислень із рухомою комою замість строгого порівняння з нулем
можна застосувати малий допуск:

```js
const EPSILON = 1e-9;
const isCovered =
  lambdaA >= -EPSILON &&
  lambdaB >= -EPSILON &&
  lambdaC >= -EPSILON;
```

Інший коректний спосіб — не виконувати ділення, а перевірити, що три значення
edge-функцій мають однаковий знак із допуском. Який би спосіб не було обрано,
у звіті потрібно пояснити його зв’язок із належністю точки трикутнику.

### Вироджений трикутник

Якщо вершини лежать на одній прямій або дві з них збігаються, площа
трикутника дорівнює нулю. Такий трикутник називають **виродженим**. Для нього
не можна обчислювати барицентричні координати діленням на площу.

```js
const signedArea = edgeFunction(vertices[0], vertices[1], vertices[2]);

if (Math.abs(signedArea) < EPSILON) {
  // Не виконувати coverage test і безпечно завершити растеризацію.
}
```

Перевірку потрібно виконати до подвійного циклу. Стартовий шаблон має
відобразити повідомлення про вироджений випадок, залишити Canvas заповненим
тлом і не створювати значень `Infinity` або `NaN` у розрахунках координат.

### Обмежувальний прямокутник

Перевіряти кожний піксель Canvas не потрібно. Трикутник гарантовано
розташований усередині прямокутника, межі якого визначають мінімальні й
максимальні координати його вершин:

```js
const minVertexX = Math.min(...vertices.map((vertex) => vertex.x));
const maxVertexX = Math.max(...vertices.map((vertex) => vertex.x));
const minVertexY = Math.min(...vertices.map((vertex) => vertex.y));
const maxVertexY = Math.max(...vertices.map((vertex) => vertex.y));
```

Для консервативної області перевірки нижні межі можна округлити вниз, а верхні
— вгору. Після цього їх обов’язково обмежують допустимими координатами
Canvas:

```js
const minX = Math.max(0, Math.floor(minVertexX));
const maxX = Math.min(width - 1, Math.ceil(maxVertexX));
const minY = Math.max(0, Math.floor(minVertexY));
const maxY = Math.min(height - 1, Math.ceil(maxVertexY));
```

Такий прямокутник може містити невелику кількість зайвих пікселів біля ребер,
але не пропускає потрібних кандидатів. Обмеження діапазонів особливо важливе,
коли частина трикутника виходить за Canvas: воно не дозволяє утворити
від’ємний індекс або записати дані за кінцем масиву.

### Запис кольору до ImageData

Для зображення завширшки `width` індекс червоного каналу пікселя `(x, y)`
дорівнює:

```js
const pixelIndex = 4 * (y * width + x);
```

Чотири послідовні елементи містять R, G, B і A. У стартовому шаблоні функція
`setPixel` додатково перевіряє межі й записує всі канали заданого кольору.
Після завершення всіх циклів об’єкт потрібно вивести одним викликом:

```js
context.putImageData(imageData, 0, 0);
```

Не потрібно викликати `putImageData` окремо для кожного пікселя. Спочатку
формують увесь масив, а потім один раз передають результат Canvas.

### Контрольний контур

Після `putImageData` дозволено окремо намалювати контур і вершини командами
Canvas. Цей шар призначений лише для перевірки: він не повинен замінювати
піксельне заповнення. У шаблоні контрольний шар вмикається прапорцем
«Показати контрольний контур і вершини».

Під час повторної растеризації спочатку створюється новий `ImageData`, тому
попередній контур не накопичується. Порівняння синього піксельного трикутника
з червоним пунктирним контуром допомагає помітити пропущені або зайві пікселі
біля ребер.

## Хід роботи

### 1. Підготовка проєкту

1. Скопіювати стартовий Vite-проєкт із файлами `index.html`, `src/main.js` і
   `src/style.css` до окремої теки.
2. Запустити проєкт у режимі розробки та відкрити сторінку в Chrome або Edge.
3. Відкрити інструменти розробника й переконатися, що в консолі немає
   помилок.
4. Указати прізвище та ім’я, групу й номер варіанта.
5. Не змінювати внутрішні розміри Canvas `640 × 480` до завершення основної
   перевірки.

### 2. Аналіз стартового шаблону

1. Знайти об’єкт `VARIANT` і масив `examples` у `src/main.js`.
2. Перенести до `VARIANT` номер, координати та кольори зі свого рядка таблиці
   варіантів.
3. Перевірити, що звичайний і зворотний контрольні приклади використовують
   координати обраного варіанта.
4. Простежити, як список на сторінці вибирає поточний набір вершин.
5. Знайти функції `fillImageData`, `setPixel`, `edgeFunction`,
   `getClampedBoundingBox`, `isPointInsideTriangle` і `rasterizeTriangle`.
6. Переконатися, що стартова версія заповнює Canvas кольором тла й окремо
   може показати контрольний контур.

### 3. Реалізація edge-функції та перевірки виродженості

1. Доповнити `edgeFunction` відповідно до наведеної формули.
2. У `rasterizeTriangle` обчислити орієнтовану подвоєну площу.
3. Вибрати й оголосити малий допуск `EPSILON`.
4. Якщо модуль площі менший за допуск, не запускати подвійний цикл.
5. Для виродженого випадку повернути `isDegenerate: true`, нуль покритих
   пікселів і коректний стан результату.

### 4. Обчислення обмежувального прямокутника

1. У `getClampedBoundingBox` знайти мінімальні й максимальні координати
   вершин.
2. Округлити нижні межі вниз, а верхні — вгору.
3. Обмежити `x` діапазоном від `0` до `width - 1`, а `y` — від `0` до
   `height - 1`.
4. Повернути об’єкт із властивостями `minX`, `minY`, `maxX` і `maxY`.
5. Вивести фактичні межі в блоці параметрів під Canvas.

### 5. Реалізація coverage test

1. У `isPointInsideTriangle` обчислити барицентричні координати або три
   значення edge-функцій.
2. Урахувати обидва можливі знаки орієнтованої площі.
3. Вважати точки на ребрах покритими, використовуючи допуск.
4. Перевірити функцію на точці всередині, зовні та приблизно на ребрі
   трикутника.

### 6. Растеризація через ImageData

1. У `rasterizeTriangle` створити `ImageData` розміром Canvas і заповнити його
   кольором `BACKGROUND_COLOR`.
2. Після перевірки виродженості отримати обмежувальний прямокутник.
3. Організувати зовнішній цикл за `y` від `minY` до `maxY` включно.
4. Усередині організувати цикл за `x` від `minX` до `maxX` включно.
5. Для кожного кандидата створити точку `(x + 0.5, y + 0.5)`.
6. Якщо coverage test успішний, записати `TRIANGLE_COLOR` функцією
   `setPixel` і збільшити лічильник покритих пікселів.
7. Після циклів один раз викликати `putImageData`.
8. Повернути зі функції фактичні `boundingBox`, `coveredPixels`,
   `isDegenerate` і стан завершеної реалізації.

Використовувати `fill()`, `fillRect()`, `stroke()` або іншу готову команду для
внутрішньої області трикутника заборонено. Метод `stroke()` у шаблоні
використовується лише для необов’язкового контрольного шару.

### 7. Перевірка контрольних прикладів

Послідовно вибрати всі приклади зі списку та для кожного натиснути
«Растеризувати».

| Приклад | Вершини | Очікувана перевірка |
| --- | --- | --- |
| Звичайний | `A`, `B`, `C` з обраного варіанта | трикутник повністю всередині Canvas |
| Зворотний порядок | `A`, `C`, `B` з обраного варіанта | ті самі покриті пікселі, що й у першому прикладі |
| Частково поза Canvas | `A(-80, 120)`, `B(360, -60)`, `C(700, 420)` | видима частина без виходу індексів за межі масиву |
| Вироджений | `A(100, 100)`, `B(320, 240)`, `C(540, 380)` | тло без заповнення та повідомлення про виродженість |

Для перших двох прикладів кількість покритих пікселів має збігатися. Увімкнути
контрольний контур і візуально перевірити положення ребер. Після цього
переконатися, що всі приклади працюють без помилок у консолі.

- коректне відсікання прямокутника розмірами Canvas;
- безпечна обробка виродженого трикутника;
- трикутник із координатами та кольорами обраного варіанта;
- працездатні чотири контрольні приклади та відсутність помилок у консолі.

2. Відомості про виконавця та групу.

4. Опис структури алгоритму растеризації.
5. Формула edge-функції або барицентричних координат.
6. Фрагменти коду обчислення меж, coverage test і запису пікселя.
